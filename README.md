# 김만식 포인트 봇

관리자가 포인트를 기록하는 디스코드 봇(엑셀 대체). 포인트 구간에 따라 역할을 자동으로 주고 회수하고,
별명 끝에 구간 숫자를 붙이고, 알림 채널에 기록을 올린다. point 봇(`DBot/point`)을 고쳐 만들었다.

**명령어는 전역 등록**이라 봇을 넣은 모든 서버에서 쓸 수 있고, **포인트·기록·구간 역할·알림 채널·별명 숫자는 서버마다 따로**다.
같은 사람도 A 서버 300P, B 서버 0P 처럼 별개다.

Node 22 + discord.js 14 + **SQLite** (`better-sqlite3`). DB 서버 없이 파일 하나(`data/kimmansik.db`)라 다른 컴퓨터로 옮기기 쉽다.

- 옮기기·백업: 봇을 끄고 `data/` 폴더를 복사하면 된다 (`kimmansik.db` 와 옆의 `-wal`·`-shm` 파일 함께).
- 다른 곳에 두려면 `.env` 의 `DB_FILE`.
- 필요한 것: Node 22 이상. `npm install` 때 `better-sqlite3` 가 그 OS 용 미리 빌드된 파일을 받는다(윈도·맥·리눅스).

## 명령어

| 명령 | 누가 | 하는 일 |
|---|---|---|
| `/포인트 [유저]` | 누구나 | 잔액 + 최근 기록 5건 (본인에게만 보임) |
| `/포인트추가 유저 숫자 [사유]` | 관리자 | 더하기 |
| `/포인트제거 유저 숫자 [사유]` | 관리자 | 빼기 (보유보다 많이는 못 뺌) |
| `/포인트지정 유저 숫자 [사유]` | 관리자 | 이 값으로 바꾸기 |
| `/포인트역할 기능:추가 포인트:0-100 역할 [역할2~5]` | 관리자 | 구간에 역할 지정. 같은 구간이면 역할을 합친다 |
| `/포인트역할 기능:제거 포인트:0-100 [역할…]` | 관리자 | 역할을 주면 그 역할만, 안 주면 구간 통째로 지운다 |
| `/포인트역할 기능:목록` | 관리자 | 구간별 역할 |
| `/포인트알림 [채널] [끄기] [역할]` | 관리자 | 알림 채널과 구간 돌파 때 멘션할 역할 1개 지정. 채널을 비우면 **명령을 쓴 그 채널**, `끄기:True` 면 알림 끔 |

관리자 = 그 서버의 서버 관리 권한. 모든 기록은 `point_ledger` 에 서버 ID 와 함께 남는다(누가·언제·사유·변경 후 잔액).
DM 에서는 명령이 보이지 않는다.

### 구간 규칙
- `0-100` = 0 이상 100 이하(양 끝 포함), `100` = 100 이상. 구간이 겹치면 양쪽 역할을 모두 받는다(추가할 때 경고).
- 판정은 **현재 잔액** 기준. 내려가면 그 구간 역할을 회수한다.
- 역할은 **한 번이라도 기록된 사람**에게만 적용한다(기록 없는 사람은 손대지 않음).
- 구간을 추가·제거하면 기록된 모든 사람에게 바로 다시 적용한다(이때는 알림 안 보냄).
- 봇 역할보다 높은 역할, 서버 주인·봇보다 높은 사람의 별명은 못 바꾼다 — 명령 응답에 ⚠️ 로 알려 준다.

### 별명
- 기본: 지금 별명 끝에 **구간 단계 번호**를 붙인다. `/포인트역할` 구간을 낮은 순으로 1, 2, 3 … 단계로 보고, 포인트가 들어가는 가장 높은 단계 번호를 쓴다.
  예) 구간 `0-99`·`100-199`·`200`(이상) → 50P `철수 1`, 150P `철수 2`, 500P `철수 3`. 어느 구간에도 안 들어가면 숫자 없음.
  구간을 추가·제거하면 단계 번호가 다시 매겨지고 기록된 모든 사람 별명이 바로 바뀐다.
- 봇이 붙인 숫자를 기억해 두었다가 바꿀 때 떼고 새로 붙인다. 32자를 넘으면 앞 이름을 줄인다.
- **uri 봇 연계 시**: uri 닉네임 양식(기본 또는 역할별)에 `{PT}` 를 넣으면 uri 가 그 값으로 닉네임을 만들고, 이 봇은 별명을 건드리지 않는다(값만 보냄).

### 알림
`/포인트알림` 채널에 올라가는 것
- **포인트 기록마다**: 📝 한 줄 — 해당 유저만 멘션
- **구간을 넘으면**(단계가 올라가면): 🎉 한 줄을 더 — 해당 유저 + `/포인트알림` 에서 고른 역할 멘션, 받은 구간 역할은 이름만 표시
- 단계가 그대로이거나 내려가면 🎉 없음. 여러 단계를 한 번에 건너뛰어도 🎉 는 한 번(도착한 단계)

```
📝 @관리자 → @철수 포인트 추가 +150P · 0P → 150P (사유: 이벤트 1등)
🎉 @운영진 @철수 님이 1단계(100~199P)에 올라섰습니다! (받은 역할: @브론즈)
```

## 커스텀 방법 (서버 관리자용)

서버마다 따로 설정한다. 아래 순서대로 하면 된다.

```
1) 구간·역할 만들기 — 낮은 구간부터. 만든 순서가 아니라 포인트 순으로 1단계, 2단계 … 가 된다
/포인트역할 기능:추가 포인트:0-99    역할:@새싹        → 1단계, 별명 "철수 1"
/포인트역할 기능:추가 포인트:100-199 역할:@브론즈      → 2단계, 별명 "철수 2"
/포인트역할 기능:추가 포인트:200     역할:@실버        → 3단계(200P 이상), 별명 "철수 3"
  · 한 구간에 역할 여러 개: 역할2~역할5 칸 사용 (같은 구간에 다시 추가해도 합쳐짐)
  · 확인: /포인트역할 기능:목록

2) 알림 켜기 — 알림 받을 채널에서
/포인트알림 역할:@운영진
  · 기록마다 @유저, 구간을 넘으면 @유저 + @운영진
  · 다른 채널로: /포인트알림 채널:#포인트기록 역할:@운영진
  · 역할 멘션 빼기: 역할 없이 /포인트알림 다시 실행
  · 끄기: /포인트알림 끄기:True

3) 포인트 기록
/포인트추가 유저:@철수 숫자:150 사유:이벤트 1등
/포인트제거 유저:@철수 숫자:20  사유:정정
/포인트지정 유저:@철수 숫자:300
/포인트 유저:@철수              ← 잔액 + 최근 기록 5건

4) 구간 고치기
/포인트역할 기능:제거 포인트:100-199 역할:@브론즈   ← 그 역할만 빼기
/포인트역할 기능:제거 포인트:100-199               ← 구간 통째로 지우기
  · 구간을 바꾸면 단계 번호가 다시 매겨지고, 기록된 모든 사람의 역할·별명이 바로 다시 맞춰진다(이때는 알림 없음)
```

주의
- 봇 역할을 자동으로 줄 역할들보다 **위로** 올려 둘 것 (아래면 못 줌 — 명령 응답에 ⚠️ 로 알려 줌)
- 서버 주인과 봇보다 높은 역할을 가진 사람의 별명은 디스코드가 못 바꾸게 한다
- 알림 역할이 "누구나 @멘션 허용" 이 꺼진 역할이면 봇에 **모두 멘션하기** 권한이 있어야 실제로 알림이 간다

## 설치·호스팅 (이 머신)

1. 디스코드 개발자 포털에서 앱을 만들고 **Server Members Intent** 를 켠다.
2. 초대 권한: 역할 관리 + 별명 관리 + 채널 보기 + 메시지 보내기 (`permissions=402656256`).
   **봇 역할을 자동으로 줄 역할들보다 위로** 올려야 한다.
3. `cp .env.example .env` 후 `DISCORD_TOKEN` 채우기.
4. `npm install && npm start` (표는 시작할 때 자동 생성, 명령은 전역 등록 — 처음 반영까지 몇 분 걸릴 수 있음)
5. 상시 구동: `sudo cp kimmansik-bot.service /etc/systemd/system/ && sudo systemctl enable --now kimmansik-bot`, 로그 `journalctl -u kimmansik-bot -f`

## uri 봇 연계 (닉네임 양식 변수 `{PT}`)

uri 쪽 기능은 SAFE-PEDBot PR #43(`feat/link-variables`)이 배포된 뒤에 쓸 수 있다. 사양 원문은 uri 레포 `link/README.md` 6장.

1. `link/kimmansik.json`(이 폴더의 초안)의 `client_id`·`guilds`(이 봇을 쓰는 uri 서버 ID 들, 비우면 uri 의 모든 서버 대시보드에 보임)를 채워 uri 레포 `link/` 에 넣고, 아무 긴 문자열을 `link/kimmansik.secret` 에 넣는다.
2. 같은 문자열을 이 봇 `.env` 의 `LINK_SECRET` 에 넣고 재시작.
3. uri 대시보드 → 봇 연계 탭 → link 폴더 다시 읽기 → 서버에 초대 → 연결 (서버마다).
4. 일반 설정 닉네임 양식에 `포인트 구간` 버튼으로 `{PT}` 를 넣는다(예: `{MC} | {PT}`, 값이 없을 때 대체: `{MC} [{PT}/"-"]`).

동작: 기동 직후와 10분마다 하트비트 → 응답 `states` 의 서버마다 `variables_in_use` 에 `PT` 가 있으면 그 서버 별명은 uri 담당.
포인트가 바뀔 때마다 그 서버·그 사람 값을, 하트비트마다 연결된 서버별 전체 값을 `/link/values` 로 보낸다(같은 값은 uri 가 무시).
uri 에 연결 안 된 서버는 연계와 상관없이 이 봇이 별명 숫자를 붙인다.
uri 담당에서 빠지면(양식에서 `{PT}` 를 빼거나 연결 해제) 다음 하트비트 때 이 봇이 다시 숫자를 붙인다.
하트비트가 잠깐 실패하면 마지막 상태를 유지한다(404 = 연계 파일 없음이면 이 봇이 맡음).
